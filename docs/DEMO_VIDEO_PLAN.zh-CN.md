## 视频 1：90 秒产品总览

### 分镜

| 时间 | 画面 | 旁白草稿 | 屏幕证明 |
|---:|---|---|---|
| 0–6 秒 | 快速切换：输入框、会议报告、左右 Alt 卡片 | “按一下 Alt，把说话变成可直接使用的文字和会议报告。” | 产品名与一句话定位 |
| 6–25 秒 | 光标放入记事本或浏览器，按右 Alt，说一段 2–3 点需求，再结束 | “右 Alt 用于日常输入。说完后可以纠错、去掉口头禅，并自动整理成分点。” | 悬浮窗状态变化与结构化结果 |
| 25–38 秒 | 中文口述，输出为英文 | “需要英文时，也可以把中文口述整理后直接输出成目标语言。” | 输入/输出语言与最终英文 |
| 38–60 秒 | 飞书或自建会议场景，两名已同意录制的说话者；按左 Alt 开始/结束 | “左 Alt 用于实时会议，同时记录麦克风和电脑播放声音。” | 左 Alt 蓝色悬浮窗、会议时长 |
| 60–75 秒 | 报告进度完成，打开历史卡片 | “结束后会生成带匿名说话人标签的结构化报告。” | 进度、概览、详情、Speaker 标签 |
| 75–84 秒 | 点击复制、导出；展示删除确认但不要真的删样例 | “报告可以复制、导出或删除，默认保存在本机。” | 四个报告交互 |
| 84–90 秒 | GitHub 页与限制字幕 | “这是一个 BYOK 开源 Demo。云端费用自理，AI 结果需要人工复核。” | GitHub 地址、BYOK、人工复核 |

### 推荐演示口述

> 我们先确认三件事。第一，周五前完成首页文案；第二，演示视频控制在九十秒；第三，发布前必须检查许可证和密钥扫描。请把这些内容整理成有逻辑的分点。

预期结果应忠实保留三件事，不添加负责人、不擅自改日期，也不要把“检查”变成已经完成。

## 视频 2：右 Alt 日常语音输入实测

### 建议结构

1. **基础输入（30 秒）**：记事本或浏览器搜索框，右 Alt 开始和结束，展示文字回到原位置。
2. **智能分点（35 秒）**：说一段包含语气词和三项任务的自然口述，展示去口头禅与 1、2、3 结构。
3. **专有词纠错（30 秒）**：先展示词典中的演示词，再说出容易听错的名称，证明最终写法被统一。
4. **翻译（30 秒）**：中文口述，输出英文；如果还要展示日文，应另用一个短句，避免观众混淆。
5. **5 秒静音门（15 秒）**：启动后保持安静，展示自动关闭且未连接云端。
6. **失败回退（20 秒）**：在一个权限/兼容性受限的输入框演示“已复制，请手动粘贴”。不要假装所有软件都能注入。
7. **限制说明（10 秒）**：说明智能整理会增加约一次模型请求时间，短输入可关闭。

### 旁白草稿

> 我先把光标放到要输入文字的位置。按一次右 Alt，悬浮窗从连接中变成“请输入语音”；说完后再按一次右 Alt。腾讯 ASR 负责转写，本地词典先处理确认过的专有词，启用智能结构化时再由模型整理措辞和分点。最后客户端会尝试把文字送回刚才的输入框；如果目标程序权限较高或不兼容，则保留到剪贴板并明确提示。

### 必测输入框

- Windows 记事本：作为最稳定基线；
- Edge/Chrome 普通网页文本框：证明浏览器场景；
- Codex 或 ChatGPT 输入框：证明 AI 对话场景；
- 微信或飞书输入框：可以展示，但要使用专门的演示账号，清空头像、联系人和历史消息。

不要把四个应用都塞进 90 秒总览。详细视频中选四个，短视频只用两个。

## 视频 3：左 Alt 实时会议纪要实测

### 演示素材

使用两名明确同意录制的参与者，或使用自行录制的双人模拟会议。建议一人通过电脑麦克风讲话，另一人的声音从会议软件/浏览器播放，使演示真正覆盖“麦克风 + 电脑声音”。不要使用未获许可的真实公司会议，也不要拿有版权的影视对白冒充会议。

### 6 分钟视频结构

| 时间 | 操作 | 验收点 |
|---:|---|---|
| 0:00–0:25 | 说明测试环境、双方同意、电脑默认输入/输出设备 | 观众知道声音来源和隐私边界 |
| 0:25–0:45 | 按左 Alt，展示与右 Alt 不同的蓝色会议悬浮窗 | 热键与模式不混淆 |
| 0:45–2:10 | 两人围绕一个明确议题对话 | 两种声音均进入转写，包含数字、否定和待确认项 |
| 2:10–2:20 | 再按左 Alt 结束 | 状态切换清楚 |
| 2:20–2:50 | 打开“会议报告”，展示正在处理的进度 | 用户知道报告在哪里等待 |
| 2:50–4:20 | 打开报告详情 | 主题、摘要、约束、新增决定、行动项、待确认问题、Speaker 标签 |
| 4:20–5:00 | 复制全文、导出 Markdown、打开报告文件夹 | 三个交付动作可用 |
| 5:00–5:20 | 点击红色叉号，先取消，再确认删除另一份专用样例 | 删除确认与取消路径正确 |
| 5:20–6:00 | 回听并指出一处 AI 需要人工复核的内容 | 不把 AI 报告宣传成最终事实 |

### 推荐模拟会议脚本

说话人 A：

> 今天只讨论演示视频。预算上限是五百元，不是五千元。目标是在下周五之前完成第一版，但发布日期还没有决定。

说话人 B：

> 我同意先做三支主视频。总览由我负责，会议演示的负责人先不要定，等素材授权确认之后再安排。

说话人 A：

> 已确认的决定只有首发做三支。五百元是预算上限，发布日期和会议演示负责人都属于待确认，不要把它们写成行动项。

这个脚本有意包含：两个说话人、500/5000 数字对抗、否定词、一个明确决定、一个有负责人的行动项，以及两个待确认事项。最终报告若把“不要定”写成已指派，必须在视频中指出它是错误，而不是剪掉。

## 视频 4：首次配置、费用与隐私（发布后补拍）

必须展示：

1. 腾讯云 AppID、SecretID、SecretKey 分别填在哪里；
2. DeepSeek API Key 填在哪里，哪些功能不开模型也能用；
3. 密钥输入过程全程打码，录屏完成后废弃/轮换测试密钥；
4. 普通 ASR 与 Speaker 2.0 是不同用量，会议模式可能产生额外费用；
5. 本地数据目录、删除方式和会议录制同意提示；
6. VPN/代理只影响网络路径，不要把代理配置包装成产品必需功能。

不要在公开视频里进入真实腾讯云账单、展示账号 UIN、手机号、余额或完整请求日志。

## 视频 5：纠错词典、记忆与总结模板（发布后补拍）

演示顺序：

1. 新增一条“常见错写 → 正确写法”；
2. 编辑、删除并取消一次删除；
3. 进行一段命中该词的转写；
4. 打开“编辑模板”，修改一个章节，再还原默认模板；
5. 解释 SQLite 本地记忆只存本机，模型只在启用相关功能时获取少量命中片段。

不要演示或宣传尚未通过价值验证的“DeepSeek 自动上下文纠错”。当前可对外证明的是用户确认词典、本地替换和既有整理流程。

## 视频 6：Android Demo（可选）

只展示已经成立的边界：

- 从 App 按钮或快捷设置磁贴启动；
- 5 秒无语音自动关闭；
- 转写与可选整理完成后复制到剪贴板；
- 由用户手动粘贴到目标应用。

不要声称 Android 能像 Windows 一样对所有第三方输入框进行全局自动注入；也不要加入尚未实现的 iOS 画面。

## 统一录制规范

### 画面

- 1920×1080，30 fps 即可；悬浮动画需要更顺滑时再用 60 fps。
- Windows 显示缩放固定为 125% 或 150%，先确认文字和下拉框没有截断。
- 桌面只保留演示所需应用，关闭通知、聊天弹窗、剪贴板历史和密码管理器提示。
- 统一使用一套虚构项目、虚构人名和演示账号，不混入真实客户信息。
- 热键操作可增加小型键盘提示，但不能挡住产品悬浮窗。

### 声音

- 旁白与功能收音最好分轨录制，避免会议播放声盖住解说。
- 使用耳机防止电脑扬声器重新进入麦克风造成回声。
- 录制前用 20 秒样例确认默认麦克风和 WASAPI Loopback 都有信号。
- 不要后期替换成与现场完全不同的“完美文字”；最终画面必须来自真实运行结果。

### 字幕与国际化

- 中文主视频配人工校对中文字幕；总览同时提供英文字幕文件。
- 英文版不要只翻译字幕：客户端切到 English，悬浮窗、模板和报告标签都应显示英文。
- YouTube 使用章节；B 站简介列出 BYOK、费用与隐私说明。

### 安全与隐私

- 使用一次性测试 API 密钥；录制结束后立即轮换或删除。
- 放大检查每一帧：密钥、账号 UIN、余额、联系人、文件绝对路径和诊断日志都不能出现。
- 真实参会者需明确同意录制和公开视频；否则使用自制模拟会议。
- 如使用第三方开放语料，需在简介和片尾按许可证署名，不能只写“来源网络”。

## 每支视频发布前的验收表

- [ ] 视频中的版本号与实际发布版本一致；
- [ ] 所有操作来自同一候选构建，没有拿旧 UI 和新报告拼接；
- [ ] 右 Alt 与左 Alt 的悬浮窗颜色、标题和热键均正确；
- [ ] 没有密钥、账号、联系人、真实会议内容或本机隐私；
- [ ] 没有把匿名 Speaker 标签说成真实身份识别；
- [ ] 没有把影子路由器说成已上线的自动节费功能；
- [ ] 没有把 AI 上下文纠错实验说成默认能力；
- [ ] 至少保留一次失败提示或人工复核说明；
- [ ] 视频简介包含 BYOK、第三方费用、录制同意和 AI 复核提示；
- [ ] GitHub URL、许可证表述和下载方式与最终发布策略一致。

## 建议制作顺序

1. 先录 3–5 分钟的右 Alt 和左 Alt 原始实测素材，不急着剪；
2. 复核文字、报告、悬浮窗和隐私，确认没有产品 Bug；
3. 从真实素材剪 90 秒总览；
4. 再分别补旁白，完成两支详细视频；
5. GitHub 源码发布后再补配置、词典和 Android 教程。

这种顺序能避免先写“完美广告脚本”，最后发现真实界面或响应时间与脚本不一致。
