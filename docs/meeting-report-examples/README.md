# 会议报告格式评审样例

以下内容均为虚构案例，不包含真实客户、员工或业务数据。三份样例分别用于检查不同风险：

1. [产品版本评审会议](./01-产品版本评审会议.md)：有明确决策、负责人、截止时间，检查行动项能否落地。
2. [客户需求访谈](./02-客户需求访谈.md)：大量信息尚未确认，检查模型会不会把意向误写为承诺。
3. [线上故障复盘](./03-线上故障复盘.md)：包含时间线、技术事实和未确认根因，检查事实边界与风险表达。

建议重点评价：

- 核心摘要是否足够短，并保留最重要的结论。
- “已确认决策”和“讨论建议”是否严格区分。
- 行动项是否包含负责人、截止时间和原文依据。
- 没有确认的信息是否明确标记为“待确认”。
- 是否需要保留“风险与分歧”“待确认问题”两个独立章节。
